# 分层记忆

本规格补充 `project-memory.md`。一个 Runmark 实例对应一个用户，记忆整体跨机器共享，沿用全站登录。

## ZCode 参考与取舍

参考 ZCode 的内容分类、短索引与命名 Agent 记忆。ZCode 的 user/project/local 是磁盘存储范围，Runmark 使用中心化存储，不照搬机器隔离：仅保留 global/project，agent_key 作为独立维度。

## 内容类型与范围

| type | 内容 | 使用时机 |
|---|---|---|
| user | 用户背景、职责、经验与稳定偏好 | 调整解释深度和协作方式 |
| feedback | 用户纠正及明确认可的工作方式 | 相似工作中应用已验证的方法 |
| project | 非代码可推导的动机、约束和决策 | 判断任务范围与方案取舍 |
| reference | 外部资料、工单、看板入口 | 查询外部系统最新事实 |

feedback/project 保留事实、Why 与 How to apply；相对日期转换为带时区的绝对日期，无依据时不补造。

- `scope=global`：跨项目，不需要仓库身份。
- `scope=project`：规范化仓库身份，同仓库跨机器、跨工作目录共享。没有仓库身份时不按主机或目录创建空间。
- `agent_key`：省略为通用，指定如 `opencode/build` 为真实命名 Agent 专属，可与两种 scope 组合。客户端产品名不等于命名 Agent。
- type 与 scope 正交；项目内的用户偏好可以是 project + user，全局反馈可以是 global + feedback。

## 提取与写入

用户明确的作用域要求优先；稳定跨项目事实保存为 global，项目约定保存为 project。先确定事实对象，再核对来源仓库；对象矛盾或范围证据不足时跳过。机器和路径可以是事实内容，但不作为记忆隔离维度。

自动提取仅保留下次独立任务仍需遵循的事实。单次交付、定时任务配置和 Skill 流程不因重复出现成为长期偏好。每项变更必须有可匹配原始消息的 quote、retention_reason、scope_reason；理由与来源修订共同保存。空 changes 是正常结果，skipped 在 job 输出中记录原因。

OpenCode 的 ctx.location 属于插件实例，不代表所有 hook/event 会话。采集、记忆注入和工具执行均核对真实 session.location；非所属目录不覆盖索引、不执行写入。已确认无 Git remote 时显式上报空 remote，清除旧仓库身份。

运维修复使用 `scripts/memory/repair-reviewed.ts`：逐条核对目录、旧 remote、记忆 ID/revision、原文片段，默认 dry-run；显式 apply 前保存受影响记录快照，事务内修正项目或使过度提取失效，保留原 ID、来源和审计修订。仅用于经核对的记录，不按名称批量猜测迁移。

来源必须是真实对话：global 可来自任意真实会话，project 必须匹配仓库，Agent 专属必须匹配来源消息身份。提取批次可跨范围原子提交，与处理游标保持事务一致。无仓库会话仍可提取明确的全局事实。

同一空间的同一事实更新原 ID；不同空间同名事实可以共存。保留修订、幂等、遗忘与恢复语义，不自动提升现有项目记录到全局。写入使用精确范围，更新和遗忘按记录实际范围操作。

## 读取与上下文

- scoped 查询指定空间，默认共享 project。
- effective 合并通用 global/project 和当前命名 Agent 对应的两层，缺少仓库时仍读取 global。
- 不读取其他仓库或其他 Agent 专属记忆；主机与目录变化不影响适用范围。
- 索引标注 scope/Agent，整体最多 200 条、25,000 字符，正文按需读取。
- 当前用户要求和当前事实优先；同主题历史约定中 project 比 global 更具体，同范围 Agent 专属更具体。不同事实不按名称静默覆盖。
- OpenCode 按 session + Agent 缓存一次索引，首次最多等待 1 秒。新会话、冷恢复及切换 Agent 获取对应快照；显式刷新获取最新内容。

## 兼容与界面

已有 project 记录保留 ID、正文、修订和来源。旧 local 记录迁入来源仓库的 project，仓库无法确定时归入 global；保留原 ID、正文、revision、来源及遗忘状态，同名冲突追加原 ID 保留两条事实。旧操作记录保留为历史证据。已无来源的旧项目可继续使用目录返回的 project_id 读取。

侧栏「记忆」保留紧凑列表与详情；工具栏仅有全局/项目、Agent、类型、状态和搜索，项目选择器仅在项目范围出现。提取开关与设置放在页头，说明折叠，不增加独立登录。

## 验收

1. 同仓库不同机器、不同目录读取相同记忆；全局跨仓库可读，项目与 Agent 隔离正确。
2. 无仓库时只使用全局；local API 参数拒绝，界面与工具 schema 不再提供该范围。
3. 旧数据升级幂等，正文、来源、修订、遗忘状态不丢失，同名迁移不覆盖事实。
4. effective 索引总预算、分页、跨范围原子提取与来源校验正确。
5. 真实 OpenCode 宿主验证索引、工具与 Agent 切换；浏览器验证紧凑筛选与详情。
