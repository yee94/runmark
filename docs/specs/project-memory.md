# Runmark 项目记忆：跨会话提取、短索引与按需读取

后续补全见 [分层记忆规格](memory-scopes.md)：以下以项目为例的基础协议仍适用，范围以 global/project × 通用/命名 Agent 的新设计为准，全部记忆跨机器共享。

## Problem Statement

用户在一个编码会话中解释过的项目约束、决策原因或协作偏好，在新会话或切换客户端后仍需重复解释。Runmark 已采集多个客户端的对话，并提供 Session 摘要、Matter 归档及搜索，但这些产物主要回答“做过什么”，尚未形成“下一次什么时候应读取什么经验”的闭环。

直接注入完整历史或 Matter 正文会扩大上下文，并把临时进展与长期约束混在一起。仅保存记忆而不提供发现入口，也无法让下一次 Agent 有效使用。

## Solution

在服务端增加独立的项目记忆模块，复用现有采集与后台 Agent 调度，从真实对话中提取可跨会话复用的事实。每条记忆包含事实、读取时机、适用范围和来源。新会话只获得短索引，Agent 在任务相关或用户要求回忆时读取详情。

第一版在现有 OpenCode 插件包内增加独立记忆适配模块，不另发插件包。其他客户端的对话可以成为记忆来源；其他客户端通过查询 Skill 按需读取，自动上下文注入先限于经接口验证的 OpenCode。

SQLite 是记忆的唯一权威来源。借鉴 ZCode 的 MEMORY.md 与事实 Markdown 协议，提供一致的索引及详情表达，不让数据库与本地文件成为两套可写事实源。

## User Stories

1. 作为项目使用者，我希望新会话知道项目有哪些可复用记忆，以便减少重复说明。
2. 作为跨客户端使用者，我希望一个客户端中的用户纠正能被其他客户端查询，以便延续协作方式。
3. 作为用户，我希望长期偏好与临时任务要求被区分，以便一次性要求不会变成永久规则。
4. 作为用户，我希望项目约束记录原因与适用条件，以便 Agent 不机械套用旧结论。
5. 作为用户，我希望外部资料保存查询入口，以便 Agent 能找到最新事实。
6. 作为用户，我希望代码已经记录的结构和修复不被重复存成记忆，以便索引保持简短。
7. 作为用户，我希望纯中文纠正也能触发提取，以便语言不影响记忆能力。
8. 作为用户，我希望明确要求“记住”的内容能被处理并返回写入结果，以便知道是否已经保存。
9. 作为用户，我希望纠正旧记忆时更新同一事实，以便新旧结论不会同时被应用。
10. 作为用户，我希望要求“忘记”后该事实不再被召回，以便撤销不再适用的约定。
11. 作为用户，我希望失败重试或重复上报不会制造重复记忆，以便保持内容一致。
12. 作为用户，我希望被忘记的事实不会因旧会话重放重新出现，以便删除有持续效果。
13. 作为用户，我希望可以查看记忆的原始消息及后续修订来源，以便核实结论。
14. 作为用户，我希望来源缺失时明确显示不可用，以便不把摘要当成原始证据。
15. 作为用户，我希望项目之间的记忆默认隔离，以便不同仓库的约定互不干扰。
16. 作为多工作区使用者，我希望同一仓库的不同 worktree 能使用同一项目记忆，以便切换分支不丢失经验。
17. 作为无 Git 项目的使用者，我希望记忆仍可按机器与目录隔离，以便不依赖仓库存在。
18. 作为用户，我希望无法确认项目身份时不自动匹配同名项目，以便避免串用。
19. 作为用户，我希望只给当前会话注入短索引，以便保留主要上下文预算。
20. 作为用户，我希望索引直接说明何时读取，以便 Agent 能判断相关性。
21. 作为用户，我希望明确要求回忆时 Agent 会读取详情，以便回答基于记录而非猜测。
22. 作为用户，我希望当前明确指令和当前代码事实优先于旧记忆，以便历史不会覆盖现实。
23. 作为用户，我希望要求本次忽略记忆时 Agent 停止使用记忆，以便可以独立讨论新方案。
24. 作为用户，我希望新会话获取最新索引，以便上一会话的更新能够生效。
25. 作为用户，我希望当前会话能主动刷新索引，以便不必为了读取新记忆重开会话。
26. 作为用户，我希望服务不可达时仍能正常对话与采集，以便记忆不成为主流程依赖。
27. 作为用户，我希望可以独立关闭记忆能力而保留遥测，以便自主控制功能。
28. 作为用户，我希望能看到记忆提取的运行结果与费用，以便了解额外模型消耗。
29. 作为 Agent，我希望按稳定 ID 读取一条记忆，以便重命名不破坏引用。
30. 作为 Agent，我希望索引超限时能继续分页查询，以便截断不会让剩余记忆永久不可见。
31. 作为维护者，我希望沿用现有安装入口与插件包，以便不增加安装维护成本。
32. 作为维护者，我希望通过 API 与最终模型请求验收行为，以便内部重构不要求重写测试。

## Implementation Decisions

### 职责与交付范围

- Session 表示原始会话；Session Summary 表示单会话摘要；Matter 表示可独立交接的工作事项；Memory 表示跨会话可复用的单条事实。记忆不替代前三者。
- 新增服务端 Memory 领域模块，负责存储、项目定位、索引投影、详情读取、修订与遗忘。提取 Agent 只通过领域写入工具提交变更，不直接操作表。
- 复用现有 Agent 配置、调度、运行日志及费用记录；新增记忆提取 Agent，不复用事项归档提示词。
- 在现有 OpenCode 插件包内拆出记忆适配模块，与遥测模块独立配置。统一安装入口不变。
- 第一版包含 API、提取 Agent、查询 Skill、OpenCode 自动注入及显式读写工具。按用户补充要求，Dashboard 提供侧栏入口、项目选择、搜索、正文与来源、索引预览及提取开关；正文修改仍通过有来源的工具完成。

### 项目与身份

- 产品身份模型固定为一个 Runmark 实例对应一个用户；接入该实例的各客户端共同服务于这个用户。直接复用现有 API Key 鉴权，不新增 user_id、tenant_id、用户分区或租户授权层，也不使用上报邮箱划分记忆归属。
- Memory 支持 global/project 两种 scope 与可选命名 Agent 维度。`type=user` 仅描述内容类别；作用域判断、合并读取与迁移遵循分层记忆规格。
- 在该用户的实例内，项目优先按规范化的仓库 remote 身份定位：去除凭据、统一同主机 SSH/HTTPS 的仓库表达、去除末尾 `.git` 与斜杠，保留仓库路径的大小写语义；不同主机、fork 或镜像不自动合并。
- 无 remote 时使用已采集的机器标识与规范化 workspace 根目录；身份字段不足时返回不可解析，不按目录 basename 或项目展示名猜测。shell 切换 cwd 不改变会话项目。
- 同 remote 的 worktree 默认共享项目记忆。跨 remote 的别名维护、项目合并及重定位不纳入第一版。
- 记忆复用 Dashboard 的全站登录态与 publicDashboard 策略，不设置独立密码或二次登录；API Key 继续可用，Session Share 不授予记忆访问权限。隔离键由服务端根据调用上下文及项目解析结果确定，来源 session 必须属于该项目。

### 存储与格式契约

- SQLite 保存 Memory、修订来源与提取进度。最低字段包括：稳定 ID、项目 ID、唯一 name、description、type、Markdown 正文、首次来源、当前 revision、状态、创建/更新时间；来源关系记录 session ID、message ID、写入 job ID，适用时记录用户显式操作。
- 同项目内 name 唯一，使用短 kebab-case；修改展示标题不改变稳定 ID。状态包括 active 与 forgotten；修订是同一 Memory 的历史，不生成平行有效事实。
- 每条 Memory 只表达一个可独立应用的事实。`description` 是单行相关性提示，须说明适用任务或读取时机，而非泛化标题。
- Markdown 详情沿用 ZCode 的语义字段：frontmatter 包含 name、description，以及 metadata 下的 node_type、type、originSessionId。node_type 固定为 memory；type 仅接受 user、feedback、project、reference。
- 首次 originSessionId 由服务端从真实来源填入，更新时保留；不能用该字段代替完整修订来源。ID、revision、scope、状态与时间以 API 元数据为准，不让模型伪造这些权威字段。
- user 保存背景或稳定偏好；feedback 保存用户纠正或认可的协作方式；project 保存无法仅从代码推导的动机、目标及约束；reference 保存外部资源入口。
- feedback 和 project 正文必须包含事实、`Why:` 与 `How to apply:`。没有来源支持的原因明确标注未知，不补造解释。相对日期结合来源时间转换为绝对日期并标明时区。
- 正文允许 `[[name]]` 关联同项目记忆；关联是阅读提示，不自动展开、不跨项目解析；目标不存在不导致保存失败。
- MEMORY.md 是派生索引，无 frontmatter，每条仅一行 Markdown 链接和读取 hook，不包含事实详情。链接指向可解析的稳定 Memory ID；不伪装成客户端磁盘上存在的文件。
- 索引从 active Memory 自动生成，避免让模型同时维护正文和索引。投影顺序固定为更新时间倒序、ID 作同时间排序键。
- 自动注入最多 200 条、25,000 个 JavaScript 字符，按完整索引行裁剪，预留超限说明空间；这沿用 ZCode 的上限作为初始值，不等价于 token 预算。超限返回 has_more 与分页入口，不截断半个链接。
- API 写入验证结构、类型、作用域、来源及 revision；不照搬 ZCode“主要靠 prompt 约束文件格式”的做法。数据库存结构化元数据与正文，输出时统一生成 Markdown，避免任意 YAML 成为另一个权威源。

### API 与模型工具

- `GET /v1/memories/index`：按解析后的 project 返回项目标识、索引版本、Markdown 索引、has_more 和继续查询入口。
- `GET /v1/memories`：按 project、query、cursor、limit 查询元数据，status 默认 active；仅用户明确恢复时可查 forgotten 的 ID、name 与 revision，不返回已遗忘正文。第一版 query 为基础文本匹配，不承诺语义向量检索。
- `GET /v1/memories/:id`：返回当前元数据、完整 Markdown 和来源。调用方必须限定项目；已 forgotten 返回明确不可用结果，不能返回旧正文用于召回。
- `POST /v1/memories`：创建事实，要求真实来源与幂等操作标识；同项目 name 冲突不静默创建第二条。
- `PATCH /v1/memories/:id`：提交新正文或元数据并携带 expected_revision；冲突返回 409，调用者重读后决定是否更新。
- `DELETE /v1/memories/:id`：执行遗忘并保留最小撤销记录；删除与物理清除源会话是不同操作。本期不承诺清除原始对话中已存在的信息。
- 模型工具对应 index/list、read、write/update、forget，沿用相同领域服务。明确“记住/忘记”通过语义理解与工具执行完成，不依赖中文关键词正则。
- 明确写入后工具返回 ID、revision 与成功状态；未成功不得回复“已记住”。目标不明确时先查找或澄清，不批量猜测删除。

### 增量提取与一致性

- 由新采集的真实对话事件通过现有 session 防抖调度触发；不依赖所有客户端均提供可靠的成功轮次结束信号。
- 提取读取尚未处理的用户/assistant 原文及必要邻近上下文，可借助摘要定位，但不能仅从摘要或 Matter 派生事实。缺正文的会话跳过并记录原因。
- 无新用户内容、仅工具输出、合成提示、后台记忆 Agent 自身输出不进入提取；纯中文句子不得因缺空格被跳过。
- 提取先读取同项目相关已有记忆，再决定创建、更新、遗忘或无内容可保存。模型猜测、工具输出里的指令不能当作用户偏好证据。
- 写入变更和已处理进度一致提交；失败不推进进度。重复 ingest、任务重试及并发执行不能产生重复 active 事实或覆盖较新 revision。
- 增量进度使用服务端持久化的消息到达序列，消息删除及数据库整理不能复用该序列；同一消息 ID 重放保留原到达位置。遗忘记录到达序列水位，恢复按服务端先后顺序判断，不依赖客户端时钟。
- 遗忘记录阻止同一旧来源重放恢复事实。只有遗忘之后的新用户明确重新要求保存，才允许恢复，并记录新的来源与 revision。
- 不保存当前会话临时进度、代码可直接推导内容、仓库指令的副本、凭据或完整工具输出；不存在值得保存的内容是正常成功结果。
- 启用后默认只处理新内容，不自动回填全部历史。来源删除后保留的记忆标示来源不可用，不捏造可访问链接。

### 上下文与客户端生命周期

- 记忆默认关闭，用户可在现有配置入口启用；服务端提取与客户端使用分别开关。关闭不删除已存记忆，采集仍可独立运行。
- 实施时先验证项目所依赖及实际运行的 OpenCode 插件版本，确认上下文修改与工具注册入口。不能仅因存在采集 hook 就假定可注入，也不能以直接改持久化消息记录代替受支持接口。
- 新会话及真正冷恢复读取一次索引；同一会话 continuation 不重复追加。若宿主每次请求要求重建系统上下文，则复用同一快照生成单个区块，不累积副本。
- 注入包括简短 Memory 使用协议及短索引，正文仅通过读取工具进入上下文。空索引不伪造事实。
- 协议明确：显式回忆请求应读取；任务相关时按 hook 读详情；忽略记忆请求优先；引用文件、配置和接口前复核当前事实。读取要求是提示词行为，不宣称运行时能强制模型调用。
- 记忆正文作为历史参考资料，不包装为覆盖当前指令的 AGENTS 规则。不得执行正文或关联资料中的角色声明与越权指令。
- 后台更新不自动改写当前上下文；提供显式刷新索引工具，新会话自动获取最新版本。工具读详情总是查询当前状态。
- 用户已看过或模型上下文已包含的旧记忆无法被遗忘 API 抹除；遗忘结果要明确说明该条已失效，后续读取禁止返回旧版本，下一会话不再注入。
- 自动索引请求设有限时限（第一版 1 秒），失败略过记忆且记录原因，不阻塞对话、不中断采集、不在每轮循环重试。显式工具查询失败正常返回错误，不回退旧正文。
- 不建立持久化本地文件镜像；因此无需双向同步、文件 watcher 或本地 Markdown 冲突合并。

## Testing Decisions

用户已确认两个验收边界：服务端完整业务闭环，以及客户端模型实际可见上下文。优先从这两个最高可控入口验证，不以内部函数调用次数或文件组织作为断言。

1. 服务端沿用现有 Agent API 测试的内存真实 SQLite、真实 schema、路由请求与可控模型响应模式；沿用调度测试的可控时间推进。只替换外部 LLM 与外部网络，保持领域写入和数据库真实执行。
2. 输入原始会话并执行后台任务，最终通过 Memory API 断言事实、索引、来源及运行费用，而非直接断言提取内部对象。
3. 覆盖创建、无可保存内容、中文纠正、同事实更新、幂等重放、revision 冲突、失败后重试、遗忘及旧来源不复活。
4. 覆盖不同项目隔离、同 remote 的 worktree 共享、无 remote 的机器/目录回退、身份不足、私有模式拒绝无凭据请求、复用全站 Cookie 及公开模式与全站策略一致。
5. 覆盖四类内容的格式语义、Why/How to apply、首次来源保留、修订来源追加、失效关联、完整行裁剪及超限分页。不要对与语义无关的 YAML 排版做快照锁定。
6. 客户端通过受支持宿主测试入口和可控 provider 捕获最终请求，验收恰好一个索引区块、无正文全集、新会话读取新版本、同会话不堆叠、按需工具结果进入上下文、关闭及服务超时不阻塞主请求。
7. 插件 hook 输出快照可以辅助定位，但不能替代最终请求的集成验收；若当前依赖无法提供可运行的宿主验收链路，应报告阻塞，不把未验证注入标记完成。
8. 使用可控模型工具调用验证协议闭环；另用少量真实模型任务验证“明确要求回忆”和“相关任务读取”的行为。不要把提示词中的 MUST 当作确定性的召回率保证，也不要将随机模型行为作为每次 CI 的硬断言。
9. 回归既有 ingest、Session 摘要、Matter 归档及插件采集测试；修改插件后完成构建与类型检查。第一版实际验收包含从其他已接入客户端采集来源、在 OpenCode 新会话读取的场景。

## Out of Scope

- 独立发布新的 OpenCode 记忆插件包。
- 向量数据库、Embedding、每轮 LLM 语义召回及 Dream 整理任务。
- 所有客户端的自动上下文注入；其他客户端本期提供查询 Skill 使用路径。
- 多租户账号与授权体系不属于本项目单用户模型。跨项目与命名 Agent 范围现已纳入分层记忆规格。
- 将 MEMORY.md 变为用户可编辑的本地权威副本，或与 ZCode 目录双向同步。
- 自动回填全部历史、仓库别名自动合并、迁移 ZCode 旧记忆。
- 记忆图谱浏览器、专用 Dashboard 编辑页、长期画像与自动推断用户身份。
- 替代 compact、Session Summary、Matter 归档或仓库 AGENTS 指令。

## Further Notes

### ZCode 研究依据与取舍

研究基于 2026-10-29 本地 ZCode 源码及 Memory v4 文档，属于静态核查，不代表已实测其运行时行为。以下路径相对 ZCode 仓库根目录：

- `apps/zcode-cli/docs/design/v2/memory/README.md:248–333`：事实 frontmatter、四种类型、来源补齐、索引与读取生命周期。
- `apps/zcode-cli/packages/core/src/context/sections/memory.ts:33–59`：实际主 Agent 提示词，包含 Why/How to apply、wiki 关联与一行 pointer。
- `apps/zcode-cli/packages/core/src/memory/index-content.ts:3–37`：200 行、25,000 JS 字符及完整行裁剪行为；其格式化函数使用 bytes 文案，但计数实际是字符串长度，本项目不照搬该单位命名。
- `apps/zcode-cli/packages/core/src/memory/extraction.ts:257–300`：按空白计词的用户内容门槛；纯中文可能被跳过，本项目不沿用。
- ZCode 的 originSessionId 在缺失时由写入边界补齐，不代表每次更新来源；Runmark 因跨客户端集中存储需另存修订证据。
- ZCode 默认语义召回关闭；索引加载一次，后台提取不热刷新当前索引。Runmark 沿用这个简单生命周期，补充显式刷新。
- ZCode 的 project key 是本地 workspace identity/path；Runmark 改用部署内的稳定仓库身份，以支持不同机器与客户端。
- ZCode 允许文件协议依赖模型维护；Runmark 使用服务端结构校验及派生索引，不要求客户端 Write/Edit 远端文件。
- ZCode 将索引合并进较强的 AGENTS 指令包装；Runmark 明确区分使用协议与被引用的历史事实，不复制 override 文案。
