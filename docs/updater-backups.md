# 自动更新：安装兼容与数据库快照

更新器始终使用 `--production --frozen-lockfile`。锁文件缺失、未知格式或安装失败都会在停服前终止，不删除锁文件重新解析依赖。Bun 1.3 遇到 v2 锁文件时，通过固定的 `bun@1.4.0` 安装；可用 `BUN_COMPAT_VERSION` 指定兼容版本。运行服务的 Bun 不会被替换。

Server 发布流水线固定 Bun 1.3.14，以继续生成旧更新器可以读取的锁文件；打包阶段执行一次 frozen production install 校验。

## 快照模式

`AGENT_TRACKER_BACKUP_MODE` 支持 `auto`（默认）、`sqlite`、`reflink`。该环境变量需要传给更新脚本进程；仅写入 Server 的 `.env` 不会自动传入 systemd transient unit。

- `auto`：在备份目录实际探测 reflink；支持则使用写时复制快照，不支持则使用 SQLite `.backup`。
- `reflink`：要求文件系统支持写时复制，且数据库和备份目录位于支持克隆的同一文件系统。短暂停止服务，克隆 DB 与残留 WAL，然后恢复服务，再检查快照完整性及记录数。需要所有数据库写入都由该服务管理。
- `sqlite`：保留在线全量备份，跨文件系统也可用，无需为了快照停服。

reflink 是块级共享：快照创建时与源文件共享磁盘块，后续写入只复制变化的块。每份快照都是独立文件，删除旧快照不影响其他快照，不需要按顺序回放增量链。`ls` 显示的逻辑大小不会变小，且 `du` 可能重复计算共享块，不能简单相加判断实际占用。

回滚继续恢复对应备份目录下的 DB/WAL。快照仍保留完整性检查，故总更新时间不等于克隆耗时；创建快照和正式部署各有一次短暂停服。不支持 reflink 时不会声称已经实现增量备份。

这是同盘更新回滚快照，不是异地容灾备份。它不能抵御整盘损坏。当前保留最近五份自动更新备份。
